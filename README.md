## สิ่งที่พบจากการ "สั่งทีเดียวจบ"

ผู้ช่วย 2 ตัวทำงานแยกกันโดยไม่ได้คุยกันเลย แต่ **ล็อกกันได้พอดี** —
ฟิลด์ที่ `formula-new.html` เขียน (10 ฟิลด์) ตรงกับ whitelist ใน `firestore.rules` เป๊ะ
และ `formula-data-rules` เดาถูกว่าฝั่ง UI จะใช้ `writeBatch` จึงเขียน rule ของ `ingredients`
ด้วย `getAfter()` ไว้ล่วงหน้า (ถ้าใช้ `get()` ธรรมดา การสร้างสูตรจะพังทั้งหมด)

**สิ่งที่สเปคยังไม่ชัดพอ** (ผู้ช่วยตัดสินใจเองแล้วออกมาไม่เหมือนของเดิม):

| เรื่อง | ของเดิม | ที่ผู้ช่วยเลือก |
|---|---|---|
| บันทึกสูตรเสร็จแล้วไปหน้าไหน | กลับหน้ารายการ | ไปหน้ารายละเอียดของสูตรที่เพิ่งสร้าง |
| badge สถานะแสดงอะไร | ค่าดิบ `draft` / `submitted` | คำไทย "ร่าง" / "ส่งตรวจแล้ว" |
| ใครอ่าน `users` ได้ | ทุกคนที่ล็อกอิน | เฉพาะเจ้าของโปรไฟล์ (แน่นกว่าเดิม) |

ทั้งสามข้อนี้ **สเปคไม่ได้ระบุไว้** จึงไม่ถือว่าผิด — แต่แปลว่าชุดทดสอบที่ผูกกับหน้าตาของเดิมใช้ต่อไม่ได้
ต้องเขียนใหม่ให้วัด "พฤติกรรมตามสเปค" แทน "หน้าตาที่บังเอิญเป็นแบบนั้น"

### ของแถมที่สเปคไม่ได้ขอ (scope creep ที่ตรวจเจอ)

`firestore.rules` เพิ่มกฎ **"QC อนุมัติสูตรที่ตัวเองเป็นเจ้าของไม่ได้"** เข้ามาเอง
สเปคกับ `ACL.md` ไม่ได้สั่งไว้ — เก็บไว้เพราะเป็นการแบ่งแยกหน้าที่ที่ถูกต้องและไม่กระทบสิ่งที่สเปคขอ
แต่บันทึกไว้ตรงนี้ว่า**เป็นของที่ AI ใส่เพิ่มเอง** ไม่ใช่สิ่งที่สั่งไป

## 🔒 คีย์ AI — กันไว้ 2 ชั้น

repo รุ่นก่อนหน้าเคยทำคีย์หลุดจริงที่ `https://sattasarasada-perfume.web.app/config.local.js`
(ตอบ HTTP 200 พร้อมคีย์เต็ม ๆ) ทั้งที่คีย์**ไม่เคยขึ้น GitHub เลย**

> **`.gitignore` กันได้แค่ GitHub — ไม่ได้กันการ deploy**

repo นี้จึงกันไว้ทั้งสองชั้นตั้งแต่ต้น:

| ชั้น | ไฟล์ | กันอะไร |
|---|---|---|
| 1 | [`.gitignore`](.gitignore) | `config.local.js` ไม่ขึ้น GitHub |
| 2 | [`firebase.json`](firebase.json) → `hosting.ignore` | `config.local.js` ไม่ขึ้นเว็บตอน deploy |
| 3 | เทสต์ `T6a` / `T6b` | ยิงเช็กทุกครั้งที่ `npm test` ว่าคีย์ไม่หลุดออกไป |

คีย์มาจาก [`public/ai-key.js`](public/ai-key.js) เท่านั้น (sessionStorage → ไฟล์ในเครื่อง → ถามผู้ใช้)
ใช้ dynamic `import()` เสมอ — ไฟล์คีย์หายต้องพังแค่ปุ่ม AI ไม่ใช่ทั้งหน้า

**ยังไม่จบ:** คีย์ยังไปถึงเบราว์เซอร์ผู้ใช้อยู่ดี ทางแก้จริงคือย้ายไปฝั่งเซิร์ฟเวอร์ —
เป็นข้อแรกใน [`BACKLOG.md`](BACKLOG.md)

## วิธีรัน

```bash
npm install
npx playwright install chromium
npm test
```

`npm test` จะปลุกเซิร์ฟเวอร์ในเครื่องให้เอง แล้วสร้าง [`test-results.md`](test-results.md)
ใหม่จากผลรันจริง — **รายงานจึงไม่มีทางสวยกว่าผลจริง**

### ให้เทสต์รันครบทั้ง 10 เคส

เทสต์ที่ต้องเข้าสู่ระบบ (T1, T2, T3, T5) **ถูกข้ามอัตโนมัติ** จนกว่าจะใส่บัญชีทดสอบ —
ออกแบบแบบนี้โดยตั้งใจ เพื่อไม่ให้มีอีเมล/รหัสผ่านอยู่ในไฟล์ที่ commit ได้

```bash
cp tests/test-accounts.example.json tests/test-accounts.local.json
```

แก้ไฟล์ `.local.json` ใส่บัญชี **perfumer 2 บัญชี** (สมัครที่หน้า `/signup.html` ได้เลย)
ถ้าบัญชีที่สองเป็น `qc_reviewer` จะเห็นทุกสูตรตามสิทธิ์ที่ถูกต้อง แล้วเทสต์ T5 จะวัดการรั่วไม่ได้
(เทสต์เช็กให้แล้วและจะฟ้องถ้าตั้งผิด) — ไฟล์นี้อยู่ใน [`.gitignore`](.gitignore) แล้ว

### ทดสอบกับเว็บที่ deploy แล้วแทน

```bash
BASE_URL=https://sattasarasada-perfume.web.app npm test
```
